# ROADMAP: TheBestDisplay 개발 계획

- 진행 방식: 작업 항목 1개당 1턴. 턴마다 개발, 문서 대조와 갱신, 검증, 커밋의 4단계 파이프라인 수행
- 커밋 규칙: 항목 1개당 커밋 1건. 작업 브랜치 `develop`. 원격 push와 `main` 병합은 사용자 승인 후
- 검증 규칙: 해당 항목 TC와 영향 범위 테스트 실행. 미실행 TC는 미실행으로 유지

## 1. 단계별 완료 조건

| 단계 | 내용 | 완료 조건 |
| --- | --- | --- |
| P0 | 조사, 선행 실험, 명세 | MRD, PRD, SRS, TC, ADR 작성. 추적성 검사 오류와 경고 0건 |
| P1 | 기반 | 창 앱과 CLI 실행. 디스플레이 목록, 정보, EDID 해석 표시. P1 TC 통과 |
| P2 | 모드와 신호 | 모드, 색 모드, HDR의 조회와 전환. 자동 복귀 동작. P2 TC 통과 |
| P3 | 진단 | 링크, 포트, 연결 경로, 진단 규칙, 이벤트, 보고서. P3 TC 통과 |
| P4 | 조정 | 밝기, DDC, 색 조정, 배치. P4 TC 통과 (장비 의존 TC는 보류 표기) |
| P5 | 확장 | 가상 디스플레이, HiDPI 스케일링, 프로파일, 문서 마감. 전체 TC 실행 |
| P6 | 제외 범위 축소 | DSC 전환, EDID 오버라이드, 사용자 정의 타이밍, 사용자 정의 스케일 해상도, 링크 제어. 장비 의존 TC는 보류 또는 미실행 표기 |
| P7 | 출시 | 버전 정보와 업데이트 확인, 공개 전 점검, README와 라이선스, 릴리스 빌드와 릴리스 노트, GitHub 릴리스와 Homebrew cask |

  - (21) 휘도 기준 동기화: 추정 휘도는 밝기 비율과 휘도가 비례한다는 가정값이며 측정값이 아님. LG TV는 EDID 최대 휘도 미보고라 사용자 지정값(400)으로만 실측. EDID 값 사용 경로, DDC와 시스템 밝기 제어 대상, 앱에서 기준값을 비워 해제하는 동작은 미확인 (해제는 명령으로 수행)
  - (22) T57 실측 중 조작 실수: 화면 구성이 바뀐 뒤의 오래된 요소 번호로 토글을 눌러 LG TV를 원본으로 한 동기화가 켜졌고 내장 디스플레이 밝기가 100%로 올라감. 바로 끄고 60%로 복원
  - (23) 채도 조정: 화면의 실제 색 변화는 측색기로 측정하지 않았고 육안 확인도 받지 않음. 확인한 범위는 계산(단위 테스트), ColorSync의 색 변환 결과, 프로파일 지정과 복귀. 색 관리를 거치지 않는 출력과 HDR 내용에 대한 효과, 앱의 조절 막대 조작, 표 방식(LUT) 프로파일은 미확인. HDR 상태별 프로파일 자동 전환(PRD-CLR-007)과 함께 쓰면 전환 시 채도 조정 프로파일이 교체됨
  - (24) 프레임버퍼 한도: 파이프별 값의 의미와 디스플레이의 화면이 어느 파이프를 쓰는지는 공개 근거 없음. 첫 파이프 값을 판정에 쓰는 근거는 실측 (LG TV 모드 목록의 최대 백킹 폭 6016과 내장 3600이 각각 첫 파이프 한도 6144와 5120 이하, 전체 HiDPI 모드가 한도 안). 한도를 넘는 스케일 해상도를 실제로 등록했을 때의 결과는 미확인 (관리자 인증 필요)
  - (25) 업데이트 확인: 터미널을 열어 `brew upgrade`를 실행하는 경로와 cask 교체는 이 기능이 들어간 버전보다 새 릴리스가 나와야 실측 가능. 실제 조회의 성공 경로(최신 버전 사용 중)는 v1.0.0 릴리스 뒤 확인. 설정 창의 토글과 지금 확인 버튼은 화면 미확인
  - (26) EDID의 HDR 선언 추가: 편집 결과의 구조와 재해석은 단위 테스트와 실제 TV EDID의 파일 편집으로 확인. 가상 EDID로 적용했을 때 시스템이 HDR 지원으로 인식하는지는 미실행 (TC-EDO-008). HDR을 선언하지 않은 실제 디스플레이는 미보유. PQ 신호를 처리하지 못하는 디스플레이에 적용하면 화면이 어둡거나 색이 틀어질 수 있음
- 원격 저장소 push와 `main` 병합: v1.0.0 릴리스로 수행 (2026-11-11, 사용자 지시). 저장소 `hungryZoo/TheBestDisplay`, 기본 브랜치 `main`, 작업 브랜치 `develop`. 저장소는 비공개로 생성한 뒤 사용자 지시로 공개 전환과 cask 등록 수행 (T66)
